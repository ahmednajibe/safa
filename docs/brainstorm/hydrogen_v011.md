## A. Change 1 — Pointing `ctranslate2` and `onnxruntime-gpu` at `torch\lib`

**DLL completeness & versions (verified in `.venv`):**
- `torch==2.5.1+cu124` (`torch\lib`, 4,325 MB) already ships every DLL imported by `onnxruntime_providers_cuda.dll` (`cublas64_12.dll`, `cublasLt64_12.dll`, `cufft64_11.dll`, `cudart64_12.dll`, `cudnn64_9.dll`) and `ctranslate2.dll` (`libiomp5md.dll`, `cudnn64_9.dll`).
- `cudnn64_9.dll` and all 7 `cudnn_*64_9.dll` sub-libs in `torch\lib` are `9.1.0.70` (identical sizes to `nvidia\cudnn\bin`), plus `torch\lib` includes `zlibwapi.dll` (`1.2.3.0`). `cublas` (`6.14.11.1242` vs `1245`) and `cufft` (`1120` vs `1121`) are minor patch deltas within CUDA 12 ABI.

**Import-order & loader pitfalls (tested empirically on this GTX 1650):**
1. **`os.add_dll_directory(torch\lib)` alone FAILS for ONNX Runtime.** Testing `InferenceSession(..., providers=['CUDAExecutionProvider'])` with only `os.add_dll_directory` failed with Win32 error 126 on `onnxruntime_providers_cuda.dll` and silently fell back to `CPUExecutionProvider`. Prepending `torch\lib` to `PATH` (as [gpu.py](file:///F:/sound_system/backend/core/gpu.py#L69-L80) already does) is **mandatory** unless `torch` was imported first.
2. **Do not rely on "`import torch` first" alone:** [transcribe_child.py](file:///F:/sound_system/backend/media/transcribe_child.py#L161-L167) calls `setup_cuda_dlls()` before `ctranslate2` without wanting `torch` init cost; keeping `setup_cuda_dlls()` adding `torch\lib` to both `os.add_dll_directory` and `PATH` works for both ORT and CT2 without importing `torch`. Note `ctranslate2` also bundles its own `ctranslate2\cudnn64_9.dll` (`9.1.0.70`) and loads it via `ctypes.CDLL` ([ctranslate2/__init__.py](file:///F:/sound_system/.venv/Lib/site-packages/ctranslate2/__init__.py#L17-L18)), while cuDNN's sub-libs (`cudnn_ops64_9.dll`, `cudnn_cnn64_9.dll`) resolve from `torch\lib`.
3. **Hidden breakage in capability detection & build checks:** [cuda_dll_dirs()](file:///F:/sound_system/backend/core/gpu.py#L37-L55) only scans `site-packages/nvidia/*/{bin,lib}`, and [capabilities.py](file:///F:/sound_system/backend/core/capabilities.py#L110) sets `cuda_dlls=bool(cuda_dll_dirs())` which gates [gpu_usable()](file:///F:/sound_system/backend/pipeline/device.py#L15) and `/api/health`. Dropping `nvidia-*` on Windows without updating `cuda_dll_dirs()` (to check for `torch\lib\torch_cuda.dll` + `cudnn64_9.dll`—not bare `torch\lib`, which CPU torch also has!) will disable GPU across the whole app. Also update [package.ps1](file:///F:/sound_system/scripts/package.ps1#L175), [test_core.py](file:///F:/sound_system/tests/test_core.py#L32-L49), and [test_cross_platform.py](file:///F:/sound_system/tests/test_cross_platform.py#L55-L108).

**Verification on GTX 1650:** Probe-only checks (`get_available_providers()`, `get_cuda_device_count()`) miss lazy cuDNN sub-lib loading. Verify in an env with no `site-packages/nvidia/` dir by running: (1) `kim_vocal_2` (`CUDAExecutionProvider`, asserting it did not fall back to CPU, via [test_separator.py](file:///F:/sound_system/tests/test_separator.py#L604)), (2) [transcribe_child.py](file:///F:/sound_system/backend/media/transcribe_child.py) `--device cuda` on ≥10 s speech, and (3) `scripts/smoke_package.py` without `--health-only`.

## B. Change 2 — Shipping `onnxruntime` (10.8 MB wheel) on CPU

- **Does `audio-separator==0.30.2` base need `onnxruntime-gpu`?** No. Inspected `.venv` metadata: base `audio-separator==0.30.2` requires neither `onnxruntime` nor `onnxruntime-gpu` (`[cpu]` / `[gpu]` extras gate them). Only `faster-whisper` and `silero-vad` unconditionally require `onnxruntime`.
- **Option (a) fails in `uv`:** As documented in [pyproject.toml](file:///F:/sound_system/pyproject.toml#L100-L109), `tool.uv.override-dependencies` is global to the lockfile and cannot be gated by root `extra == 'cu124'`. Keeping the override blocks `onnxruntime` from `cpu`; removing it pulls both `onnxruntime` and `onnxruntime-gpu` in `cu124`, clobbering `site-packages/onnxruntime/` during `uv sync --extra cu124`.
- **Least fragile choice — centralized post-export helper (refined Option b):** `uv.lock` *already* stores `onnxruntime==1.20.0` `win_amd64` (10.8 MB) and `manylinux_x86_64` (12.7 MB) wheel hashes, and `onnxruntime` vs `onnxruntime-gpu` have the exact same 6 dependencies (`coloredlogs`, `flatbuffers`, `numpy`, `packaging`, `protobuf`, `sympy`). Rather than duplicating sed/regex hacks across the 4 export callers ([build-installer.ps1](file:///F:/sound_system/scripts/build-installer.ps1#L136), [package.ps1](file:///F:/sound_system/scripts/package.ps1#L148), [package-unix.sh](file:///F:/sound_system/scripts/package-unix.sh#L79), [build-wheel.py](file:///F:/sound_system/scripts/build-wheel.py#L79)), add one shared `scripts/export_requirements.py` that runs `uv export` and, for `cpu`, swaps the `onnxruntime-gpu==1.20.0` block to `onnxruntime==1.20.0` using hashes read directly from `uv.lock`. Update [test_variant_extras.py](file:///F:/sound_system/tests/test_variant_extras.py#L116-L130) accordingly (note CI in [release.yml](file:///F:/sound_system/.github/workflows/release.yml#L114) runs `uv sync --extra cpu`, which would still install `onnxruntime-gpu` unless CI uses `--extra cpu` only for metadata/models, which is fine).

## C. Change 3 — Inno 6.4.3 Responsive Progress & Safe Cancel

- **Don't use `ExecAndLogOutput`:** While `ExecAndLogOutput(..., ewWaitUntilTerminated, ...)` ([PowerShell.iss](file:///F:/sound_system/tools/innosetup/app/Examples/PowerShell.iss#L63)) pumps messages, it does not return a child PID/handle, and `TOutputProgressWizardPage` disables Cancel during `ssPostInstall`—making safe tree termination impossible.
- **Don't rely on `AppProcessMessage` or bare `Exec(..., ewNoWait)`:** Inspected `Setup.e32` in Inno 6.4.3—`AppProcessMessage` does not exist, and `Exec(..., ewNoWait)` returns no PID.
- **Recommended implementation:**
  1. Launch `powershell.exe` from `[Code]` via WinAPI `CreateProcessW` inside a Windows Job Object (`CreateJobObjectW` + `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` + `AssignProcessToJobObject`), or record `$PID` + `taskkill /T /F /PID`.
  2. Loop on `WaitForSingleObject(hProcess, 100)` while pumping messages with WinAPI `PeekMessageW`/`TranslateMessage`/`DispatchMessageW` (`user32.dll`).
  3. Have [install-runtime.ps1](file:///F:/sound_system/scripts/install-runtime.ps1) write `stage|bytes_done|bytes_total` to a small status file (avoid reading `install.log`, locked by `Start-Transcript`) by polling `$env:UV_CACHE_DIR` delta (baseline subtracted so re-installs don't jump straight to 100%) + `pyroot` size in a background runspace/job while `uv` executes.
  4. **Critical Inno bug to avoid:** `TOutputProgressWizardPage.SetProgress(Pos, Max)` takes signed 32-bit `Longint` (max 2.14 GB)—pass **MB** (or 0..10000 permille), never raw bytes!
  5. Re-enable `WizardForm.CancelButton.Enabled := True` while `UvProgressPage` is visible (skipped when `WizardSilent`); on Cancel confirmation, call `TerminateJobObject(hJob, 1)` + clean up partial `{app}\python`, `{app}\pyroot`, and `installed.json` ([online.iss](file:///F:/sound_system/packaging/windows/inno/online.iss#L230) writes `installed.json` *before* `RunRuntimeInstall()`, leaving a broken install on abort!).

## D. Risks, Bugs & Missing Wins

1. **Multi-GB leftovers in `DataDir`:** [install-runtime.ps1](file:///F:/sound_system/scripts/install-runtime.ps1#L28) keeps `UV_CACHE_DIR` (`<DataDir>\tmp\uv-cache`) forever after install—wasting ~3 GB on user disks. Wipe `uv-cache` on successful install (or pass `--no-cache` if uv supports it with `--require-hashes`).
2. **Stale size copy in UI:** Update "~6 GB / ~2 GB" strings in [online.iss](file:///F:/sound_system/packaging/windows/inno/online.iss#L81-L84) and [common.iss](file:///F:/sound_system/packaging/windows/inno/common.iss#L18-L21) after measuring the post-Change-1/2 download (~3.0 GB GPU, ~1.7 GB CPU).
3. **`offline-gpu.iss` slice check ([lines 92–117](file:///F:/sound_system/packaging/windows/inno/offline-gpu.iss#L92-L117)):** Without `slicecount.txt`, requiring `-1.bin` + contiguous slices still misses a missing *last* slice (`-2.bin`) if 2 slices remain. However, dropping ~1.7 GB of `nvidia-*` wheels may reduce `offline-gpu` to `setup.exe` + `-1.bin` only (1 slice, deterministic without `slicecount.txt`). Also fix line 110's error message (`'  setup-' + IntToStr(I) + '.bin'`) to print the real filename `Safa-{#AppVer}-win-x64-gpu-offline-setup-%d.bin`.
4. **Simpler extra size win:** None comparable without dropping features—removing Windows `nvidia-*` wheels (~1.72 GB download / 2.73 GB installed) + CPU `onnxruntime` (~256 MB download / ~730 MB installed) + clearing `uv-cache` after online install captures almost all safe savings.

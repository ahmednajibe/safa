### A. Server-side Save As vs. debugging Chrome `AbortError`
Server-side Save As is the right direction for desktop installs. In [save.ts:103-107](file:///F:/sound_system/frontend/src/lib/save.ts#L103-L107), `window.showSaveFilePicker` is already the first `await` (the `trace` calls at `L98-101` are unawaited), yet Windows Chrome still aborts on Desktop/OneDrive-redirected paths due to Chrome's internal path/Safe-Browsing/cloud-placeholder checks—and Firefox lacks FS Access altogether ([save.ts:9-11](file:///F:/sound_system/frontend/src/lib/save.ts#L9-L11)). Tuning `id`/`types`/`startIn` only works around browser heuristics and never gives Firefox or "Show in folder" (`saved_path`) parity. Keeping `503 picker_unavailable` → `downloadJobFile` ([actions.ts:178-182](file:///F:/sound_system/frontend/src/actions.ts#L178-L182)) cleanly covers Docker/headless.

### B. Security & validation
- **Origin/CSRF**: [main.py:234-253](file:///F:/sound_system/backend/main.py#L234-L253) already blocks non-loopback `Host`, `Sec-Fetch-Site: cross-site`, and foreign `Origin`/`Referer` on `POST`. One subtlety: `L251` skips the origin check when both `Origin` and `Referer` are absent (`src is not None`, meant for `curl`/tests). Requiring a JSON body (even `{}` parsed by Pydantic) forces a CORS preflight and rejects simple cross-site `<form>`/`no-cors` requests; combined with a native OS dialog requiring user confirmation, CSRF risk is minimal.
- **Path validation**:
  - **Drive root quirk**: `validate_output_dir` ([output_dir.py:78-79](file:///F:/sound_system/backend/core/output_dir.py#L78-L79)) rejects drive roots (`resolved.parent == resolved`); reusing it on `target.parent` blocks saving directly to `D:\out.wav`. Decide whether to allow that.
  - **Symlink overwrite**: `validate_output_dir` checks `resolved != lexical` on the directory (`L76`), so also check `target.is_symlink()` before writing/replacing so an existing symlink cannot redirect the write into `DATA_DIR`/repo.
  - **Overwrite vs. `_auto_copy`**: `_auto_copy` ([output_dir.py:173-193](file:///F:/sound_system/backend/core/output_dir.py#L173-L193)) calls `_claim_target` to rename to `name (2).ext`. For Save As (`confirmoverwrite=True`), copy to `.<name>.<uuid>.tmp` in `target.parent` and `os.replace(tmp, target)` directly—skip `_claim_target`.
  - **Sharing `_PICK_LOCK`**: Share one lock between `pick_output_dir` ([settings.py:25](file:///F:/sound_system/backend/api/settings.py#L25)) and Save As so two dialogs cannot race.

### C. `tkinter.asksaveasfilename` pitfalls
- **Z-order & focus**: `_PICKER_SCRIPT` ([output_dir.py:27-47](file:///F:/sound_system/backend/core/output_dir.py#L27-L47)) uses `-topmost 1`, which usually works, though Windows denies `SetForegroundWindow` to background processes; adding `root.lift()` / `root.focus_force()` helps. DPI (`SetProcessDpiAwarenessContext(-4)`) is already handled.
- **Arabic paths (latent bug)**: `run_picker` ([output_dir.py:121](file:///F:/sound_system/backend/core/output_dir.py#L121)) passes `text=True` *without* `encoding="utf-8"`. On Windows without `PYTHONUTF8=1`, `subprocess.run` decodes stdout using the ANSI code page (e.g. `cp1252`), corrupting Arabic paths—fix both child (`PYTHONUTF8=1` or `stdout.reconfigure(encoding="utf-8")`) and parent (`encoding="utf-8"`).
- **Long paths**: Windows `GetSaveFileNameW` can hit `MAX_PATH` (260 chars) on non-long-path-enabled systems; surface write/dialog errors cleanly rather than crashing.
- **Extensions**: Pass `defaultextension=ext` and `filetypes` for the output format, *and* enforce the output's real extension server-side if the user omits or changes it (since no transcode happens on Save As).
- **Platform/Tk**: The `.venv` uses CPython 3.11.9 with Tk 8.6; `uv` standalone builds include Tcl/Tk on Windows/macOS/Linux desktop. In Docker ([Dockerfile:18](file:///F:/sound_system/Dockerfile#L18), `python:3.11-slim-bookworm`), `tkinter`/X11 libs are absent—`run_picker` catches `ImportError`/non-zero exit and raises `PickerUnavailable` → `503`.

### D. Request lifecycle & concurrency
Blocking a sync `def` route (like `pick_output_dir` in [settings.py:84](file:///F:/sound_system/backend/api/settings.py#L84)) for up to 120s uses 1 of AnyIO's 40 worker threads, which is fine because `_PICK_LOCK` caps concurrency at 1, and local browser `fetch` ([client.ts:42-54](file:///F:/sound_system/frontend/src/api/client.ts#L42-L54)) won't time out at 120s.
**Improvement**: make the new endpoint `async def` using `asyncio.create_subprocess_exec` and poll `request.is_disconnected()` (as [jobs.py:304](file:///F:/sound_system/backend/api/jobs.py#L304) does) to `proc.kill()` if the user closes/reloads the tab—otherwise an abandoned dialog stays open and blocks future saves with `409 picker_busy` for 120s. Note: for large multi-GB outputs, consider copying after releasing `_PICK_LOCK` (and update UI from "Waiting for folder…" to "Saving…").

### E. Anything simpler?
Plain browser download (`<a download>`, [save.ts:142-149](file:///F:/sound_system/frontend/src/lib/save.ts#L142-L149)) is the only simpler zero-dialog option, but it sacrifices destination choice, overwrite confirmation, and `saved_path` / "Show in folder". Extending [output_dir.py](file:///F:/sound_system/backend/core/output_dir.py) reuses existing tested machinery and is simpler than debugging Chrome's FS Access implementation.

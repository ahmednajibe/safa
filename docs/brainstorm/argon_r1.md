### 1–3. Correctness, Security & Error-Handling Findings (Most Severe First)

1. **[media.py:350-372](file:///F:/sound_system/backend/api/media.py#L350-L372), [db.py:18-58](file:///F:/sound_system/backend/db.py#L18-L58) — HIGH (Correctness / Orphans / 500)**
   - **Scenario:** User calls `DELETE /api/media/{id}` after any job on that media has `completed`, `failed`, `cancelled`, or `interrupted`, or while `_prepare` ([media.py:256-260](file:///F:/sound_system/backend/api/media.py#L256-L260)) is still running. `delete_media` only rejects `queued`/`running`, deletes `mdir` on disk first, then executes `DELETE FROM media` which raises unhandled `sqlite3.IntegrityError` (HTTP 500) due to `jobs.media_id REFERENCES media(id)` with `PRAGMA foreign_keys=ON`; if `_prepare` is active, it recreates `playback.m4a`/`peaks.json`/`prep.log` in `mdir` after `rmtree`.
   - **Fix:** Track/cancel `_prepare` before deletion, delete or cascade terminal jobs in SQLite inside one transaction *before* `shutil.rmtree(mdir)`, or add `ON DELETE CASCADE` on `jobs` and `job_files`.

2. **[main.py:42-55](file:///F:/sound_system/backend/main.py#L42-L55), [jobs.py:249-283](file:///F:/sound_system/backend/api/jobs.py#L249-L283), [media.py:187-235](file:///F:/sound_system/backend/api/media.py#L187-L235) — HIGH (Security: Cross-Origin CSRF & Disk-Fill DoS)**
   - **Scenario:** No `Origin`/`Referer` check exists on `POST`/`PUT`/`DELETE` (SPEC §12). Any foreign browser tab can send CORS-simple `fetch("http://127.0.0.1:8790/api/jobs/<id>/cancel", {method:"POST", mode:"no-cors"})` or `/retry` (no custom headers/preflight) to kill or re-queue GPU jobs, or stream up to 4 GB to `POST /api/media` before header rejection. Also, sending `Content-Length: 1` with a 4 GB body bypasses the per-chunk `free_space_bytes` check at [media.py:220](file:///F:/sound_system/backend/api/media.py#L220) (`if content_length is None`).
   - **Fix:** Enforce `Origin`/`Referer` host allowlist (`127.0.0.1:8790`/`localhost:8790`) in middleware before body read, validate `X-Filename` before streaming, and check `written > content_length` and disk space on every chunk.

3. **[media.py:307-318](file:///F:/sound_system/backend/api/media.py#L307-L318), [storage.py:27-37](file:///F:/sound_system/backend/media/storage.py#L27-L37) — HIGH (Security / DoS / Race)**
   - **Scenario:** `GET /api/media/{id}/peaks?stream=1` synchronously decodes a full 48 kHz float32 `stream_1.wav` on the request thread without a lock or cleanup. Concurrent requests for the same stream overwrite/read `stream_1.wav` simultaneously (corrupting output or crashing on Windows file locks) and permanently leave multi-GB WAVs per stream on disk; `media_id`/`job_id` also lack strict hex-UUID validation in `media_dir`/`job_dir`.
   - **Fix:** Validate IDs against `^[0-9a-f]{32}$`, guard on-demand stream peak generation with a per-`(media_id, stream)` lock, compute peaks to a temp file, and unlink `stream_{N}.wav` in `finally`.

4. **[supervisor.py:135-165](file:///F:/sound_system/backend/jobs/supervisor.py#L135-L165), [supervisor.py:213-240](file:///F:/sound_system/backend/jobs/supervisor.py#L213-L240) — HIGH (Correctness: Cancel/Spawn Race)**
   - **Scenario:** `_loop` pops a `queued` job (`L200`) and spawns `Popen` (`L221`) before calling `mark_running` (`L237`). If `POST /cancel` runs in that window, `cancel()` sees `job.state == "queued"` (`L141`), marks it `cancelled`, and returns without killing `proc`; the worker then runs un-killed while `mark_running` silently no-ops (`WHERE state='queued'`). `cancel()` also blocks the HTTP thread for up to 7 s.
   - **Fix:** Hold `self._lock` across `cancel_requested` check, `Popen`, `self._current` assignment, and `mark_running`.

5. **[silence_plan.py:107-122](file:///F:/sound_system/backend/media/silence_plan.py#L107-L122) — HIGH (Correctness: `shorten` Pause Math)**
   - **Scenario:** `blocks` already include `pad_s` on each side (`prev_end = b0 + pad_s`, `a = a1 - pad_s`), and `action="shorten"` adds `half = keep_pause_s / 2` to both (`prev_end + half`, `a - half`). This keeps `2 * pad_s + keep_pause_s` of silence instead of `keep_pause_s`, and whenever `raw_gap <= 2 * pad_s + keep_pause_s` (e.g. any 0.30–0.45 s pause at defaults `min_silence_s=0.3, pad_s=0.1, keep_pause_s=0.25`), `prev_end + half >= a - half` so `_merge` fuses the blocks and removes 0 s.
   - **Fix:** Add `max(0.0, (keep_pause_s - 2 * pad_s) / 2.0)` (clamped to `(a - prev_end) / 2`) so total kept silence equals `min(raw_gap, max(2 * pad_s, keep_pause_s))`.

6. **[video_render.py:54-71](file:///F:/sound_system/backend/media/video_render.py#L54-L71) — MEDIUM (Correctness: Video FPS Scaled by Speed)**
   - **Scenario:** When `speed != 1.0`, `_filter_script` appends `,setpts=PTS/{speed},fps={fps * speed}`, emitting a container at `fps * speed` (e.g. 60 fps at `2x` → 120 fps, or fractional 31.25 fps at `1.25x` on 25 fps) instead of CFR `fps`, breaking NVENC macroblock/level limits and frame-grid alignment.
   - **Fix:** Use `,setpts=PTS/{_fmt(speed)},fps={_fmt(fps)}` so output stays CFR at `fps`.

7. **[cutter.py:122-160](file:///F:/sound_system/backend/media/cutter.py#L122-L160), [silence.py:160-163](file:///F:/sound_system/backend/operations/impl/silence.py#L160-L163) — MEDIUM (Correctness: Composed Snap Drift)**
   - **Scenario:** When `silence` follows `trim` on a video job, `new_tl.snap(ctx.fps)` rounds segment edges in source time outward by up to `0.5 / fps` into `parent`'s removed region; `input_intervals(parent, new_tl)` clamps the audio intervals to `parent`'s span while `new_tl` (used by `render_video`) keeps the wider snapped span.
   - **Fix:** Intersect `new_tl.snap(ctx.fps)` with `parent.kept_spans_src()` (or snap only inside `parent` boundaries) before computing `input_intervals`.

8. **[store.py:203-240](file:///F:/sound_system/backend/jobs/store.py#L203-L240) — MEDIUM (Correctness: Throttled Stage-Completion Drop)**
   - **Scenario:** `update_progress` drops events when `p.stage == last_stage` and `< 0.25 s` elapsed. Fast ops (`trim`, `channel`, `highpass`, short `silence`) finish in `< 250 ms`, so their closing `stage_pct=1.0` and `message_code` are dropped from the `jobs` table and SSE `state` stream.
   - **Fix:** Bypass the 0.25 s throttle when `p.stage_pct == 1.0`, `p.message_code is not None`, or `p.warning_code is not None`.

9. **[silence.py:45-61](file:///F:/sound_system/backend/operations/impl/silence.py#L45-L61), [breaths.py:171-185](file:///F:/sound_system/backend/media/breaths.py#L171-L185) — MEDIUM (Correctness: Breath Clamp Fails on Long Pauses)**
   - **Scenario:** `_breaths_near_splices` passes `[b0 - 1.0, a1 + 1.0]` to `detect_breaths`, which computes `speech_db` as P85 of all frames in the slice. If a pause is `> 11.3 s`, speech is `< 15%` of the slice, so P85 lands in silence (`speech_db - 4 <= floor_db + 3`) and `detect_breaths` returns `[]`.
   - **Fix:** Compute `_level_stats` once on the whole file (or pass `speech=[(0, margin_s), (slice_len - margin_s, slice_len)]` into `_level_stats` and take P85 over speech frames).

10. **[transcribe.py:353-364](file:///F:/sound_system/backend/media/transcribe.py#L353-L364), [runner.py:224-250](file:///F:/sound_system/backend/pipeline/runner.py#L224-L250) — LOW (Progress Regression & Leftover Output Files)**

    - **Fix:** Pass `device="cpu"` on fallback and clean `outdir` in `worker.py` when marking a job `failed`.

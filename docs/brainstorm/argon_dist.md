### 1. Real `.exe` for This Python + Torch App
* **Do NOT freeze the whole app with PyInstaller/Nuitka:** Packing `torch==2.5.1+cu124`, `onnxruntime-gpu`, `ctranslate2`, and 9 `nvidia-*` wheel trees produces a 4–5 GB bundle, breaks dynamic loaders (`audio-separator`, `deepfilternet`, `pkg_resources`), breaks `sys.executable -m backend.worker` / `transcribe_child` / `model_download` in [supervisor.py](file:///F:/sound_system/backend/jobs/supervisor.py#L264-L272), and triggers severe Windows Defender false positives.
* **Recommendation — Tiny native C# stub `.exe` wrapping M10b’s private `python\python.exe`:**
  * Compile a ~60 KB native stub (`Safi.exe`) during [package.ps1](file:///F:/sound_system/scripts/package.ps1) using Windows' built-in `csc.exe` (or Go/Rust) with an embedded `.ico` and version manifest—no extra toolchain or AV-flagged PyInstaller bootloader.
  * **Why it fits:** `python\python.exe` remains `sys.executable`, so worker, whisper-child, model-downloader, and tkinter-picker subprocesses work untouched.
  * **UX & lifecycle:** Keep the **console window visible** (bilingual EN/AR logs + first-run 590 MB model progress), attach a Windows Job Object (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`) so closing the window kills `uvicorn` + `ffmpeg` children cleanly, and reuse the `/api/health` single-instance probe from [launcher-lib.ps1](file:///F:/sound_system/scripts/launcher-lib.ps1#L34-L68) (if already running, open browser and exit 0).

### 2. Installers, OS Matrix & GitHub’s 2 GB Asset Limit
* **Critical sizing constraint:** GitHub Releases cap individual assets at **2 GiB**.
  * **Windows CPU** (`-win64-cpu.zip` / `-setup.exe`): **~480–550 MB** (fits in one asset).
  * **Windows GPU** (`-win64-gpu`): **~2.6–4.6 GB** compressed (`torch+cu124` + 9 `nvidia-*` wheels + `onnxruntime-gpu`). **Cannot be a single GitHub Release file.**
* **Windows (3 install paths like Wird):**
  1. **Inno Setup per-user installer (`<App>-<ver>-win-x64-setup.exe`, ~500 MB):** `PrivilegesRequired=lowest`, installs CPU base + `python\` + `tools\ffmpeg` to `%LOCALAPPDATA%\Programs\<App>`, creates Start Menu & Desktop shortcuts. At install time (or via `install.ps1`), auto-detects NVIDIA (`nvidia-smi`) and offers to fetch the GPU wheel pack (split `<App>-gpu-runtime.zip.001` + `.002` ≤1.8 GB each from the release, or via bundled `uv`).
  2. **Portable ZIPs:** `-win64-cpu.zip` (~500 MB) and split GPU archive (or generated by `install.ps1`).
  3. **One-line PowerShell:** `irm https://github.com/ahmednajibe/<repo>/releases/latest/download/install.ps1 | iex` — checks `nvidia-smi` and free disk space, downloads CPU or GPU variant, extracts, and adds shortcuts.
* **macOS (Apple Silicon) & Linux:**
  * **One-line `curl -fsSL .../install.sh | sh`** + **From source (`uv`)**: Installs standalone Python 3.11 via `uv`, ensures `ffmpeg`, creates `~/Applications/<App>.command` (macOS) or `~/.local/bin` + `.desktop` launcher (Linux).
  * **macOS Gatekeeper without a paid Apple ID:** Unsigned `.dmg`/`.app` bundles get quarantined ("damaged app"). Installing via `curl ... | sh` (or running `xattr -dr com.apple.quarantine`) bypasses Gatekeeper cleanly. Apple Silicon uses standard PyPI `torch==2.5.1` (CPU/MPS) + CPU `onnxruntime`/`ctranslate2`.
* **Code changes needed for macOS/Linux:**
  * [output_dir.py](file:///F:/sound_system/backend/core/output_dir.py#L126-L130): `reveal_in_explorer` hardcodes `explorer.exe /select,` — branch on `sys.platform` (`open -R` on `darwin`, `xdg-open` on `linux`). `_PICKER_SCRIPT` already catches `ctypes.windll`, and 503 `picker_unavailable` gracefully falls back to paste-a-path.
  * [ffmpeg.py](file:///F:/sound_system/backend/core/ffmpeg.py#L20-L31) & [gpu.py](file:///F:/sound_system/backend/core/gpu.py#L53-L71): Already cross-platform (`_exe` checks `os.name == "nt"`, `shutil.which` fallback, `setup_cuda_dlls` is a safe no-op without `nvidia/*/bin`).
  * **Launcher:** Move startup orchestration from [start.ps1](file:///F:/sound_system/scripts/start.ps1) into a Python module (`python -m backend.launcher`) called by `Safi.exe`, `start.bat`, and `start.sh`.
  * **Now vs. Later:** Ship the small cross-platform Python fixes + `start.sh` / `install.sh` **now** (low effort, unlocks macOS/Linux via `uv`), defer heavy AppImage/DMG bundles to later.

### 3. Models & User Data Storage
* **Download on first run (keep installer small):** Core models are **~590 MB** ([models_manifest.py](file:///F:/sound_system/backend/core/models_manifest.py)), optional **+1.7 GB**. Use the existing SHA-256 + resumable `.part` downloader in [model_download.py](file:///F:/sound_system/backend/core/model_download.py).
* **Data/Models directory resolution in [paths.py](file:///F:/sound_system/backend/core/paths.py):**
  * **Dev / Portable ZIP mode** (default when `.venv` or `PORTABLE` marker existsnext to `.exe`): Keep `ROOT / "data"` and `ROOT / "models"` so unzipping to `D:\` never touches `C:`.
  * **Installed mode** (`INSTALLED` marker written by Inno Setup, or `SOUND_SYSTEM_DATA_DIR` set): Store `data/` and `models/` in `%LOCALAPPDATA%\<App>` (Windows), `~/Library/Application Support/<App>` (macOS), `~/.local/share/<app>` (Linux)—with an Inno Setup page allowing users with tiny `C:` drives to pick a data folder on `D:\`.
  * **Updates & migration:** Re-running `setup.exe` overwrites `%LOCALAPPDATA%\Programs\<App>` while leaving the data/models folder intact; dev checkouts continue using `ROOT / "data"` with zero migration friction.

### 5. Release Pipeline (GitHub Actions)
* **`release.yml` on `v*` tags:** Verifies tag matches `version` in [pyproject.toml](file:///F:/sound_system/pyproject.toml#L3).
* **CI Matrix:**
  * `windows-latest`: `npm ci && npm run build`, compiles `.exe` launcher, runs `scripts/package.ps1 -Variant cpu`, builds Inno Setup installer (`iscc`), builds split GPU archive, runs **CPU smoke test** (starts packaged `.exe -NoBrowser`, polls `/api/health` and `/api/operations`, runs a 2 s CPU pipeline job—no GPU needed on runner).
  * `ubuntu-latest` & `macos-latest`: `uv sync` (CPU profile), runs `pytest -m "not slow"`, smoke-tests `install.sh`.
* **Release artifacts:** Generates `SHA256SUMS.txt`, embeds `LICENSE` + `LICENSES/third-party.txt`, signs `.exe` if `WINDOWS_PFX_BASE64` secret exists, and creates a **Draft Release**.

### 6. Key Risks & M10c Acceptance Tests
* **Risks:** (1) GPU zip exceeding GitHub’s 2 GB limit (solve via split archive or `install.ps1` fetching CUDA wheels); (2) SmartScreen / Defender warnings on unsigned `.exe` (mitigate with clean C# stub instead of PyInstaller + documented SmartScreen step); (3) Installed mode filling a small `C:` drive (mitigate with configurable data dir in installer).
* **Acceptance Tests:**
  * `test_exe_launcher_lifecycle`: Starts `.exe`, verifies `/api/health`, second `.exe` exits 0 (single-instance), killing `.exe` leaves zero orphan `python`/`ffmpeg` processes.
  * `test_paths_installed_vs_portable`: Verifies `PORTABLE` vs `INSTALLED` / `SOUND_SYSTEM_DATA_DIR` resolution with Arabic + space paths.
  * `test_cross_platform_reveal_and_picker`: Tests `reveal_in_explorer` platform dispatch (`win32`/`darwin`/`linux`) and picker fallback.
  * `test_inno_silent_install_upgrade_uninstall`: Runs `setup.exe /VERYSILENT /DIR=...`, verifies reinstall keeps `data/app.db` + `models/`, uninstall removes app binaries only.
  * `test_readme_and_llms_txt_sync`: Verifies EN/AR READMEs and `llms.txt` contain valid install URLs, version, and SHA256 references.

## M9a Task 0 — Backend prerequisites (found in review)
1. **Processed peaks:** after the encode stage the runner writes `output/peaks.json` from the final 48 kHz WAV (before `work/` is deleted) using `compute_peaks`; `GET /api/jobs/{id}/peaks` (404 until completed).
2. **HTTP Range on job outputs:** `/api/jobs/{id}/files/{name}` reuses media.py's `_file_response` (206 + correct content-type), keeping the UTF-8 `Content-Disposition`.
3. **`files` in `GET /api/jobs` rows and every SSE `state` event.**
4. **Localizable stage identity:** progress/stage fields carry `stage_id` (op id or `decode` / `encode` / `video`) alongside any English text; the UI translates `stage_id`.
5. **`eta_sec`**: written from `estimates.py` factors × remaining stages, refined with measured stage seconds; null while unknown.
6. **Saving backend (SPEC §12):** `settings` table; `POST /api/settings/output-dir/pick` (subprocess tkinter dialog: DPI aware, topmost, single-flight 409, 120 s timeout, 503 `picker_unavailable`), `PUT/DELETE /api/settings/output-dir`, validation, atomic non-colliding auto-copy (never previews, never fails the job → `auto_save_failed`), `job_files.saved_path`, `POST /api/jobs/{id}/files/{name}/reveal`; **Origin/Referer check on all state-changing endpoints** (403 `bad_origin`).
- Tests for each.

## M9a — Workflow core (frontend)
